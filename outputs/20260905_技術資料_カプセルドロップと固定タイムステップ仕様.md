# スターヴァイパー — 固定タイムステップ／カプセルドロップ仕様

対象: `game/js/logic.js` に純関数を置き、`game/js/game.js` が呼び出す。  
前提: 自機移動で敵・背景が加速する不具合は、可変フレーム（`requestAnimationFrame` 1回 = シミュレーション1回）が原因。本仕様の時計に置き換える。ゲームコードは本資料では書かない。

---

## 0. 現状と目標（設計判断の根拠）

### 現状（60fps換算）

| 項目 | 値 |
|---|---|
| 波間隔 | `waveInterval`: 序盤102f（1.70秒）、中盤以降92f（1.53秒）。ステージが上がるとさらに短い |
| 赤波 | 5波中2波。赤3機が**全員**ドロップ |
| 通常fan | 1機あたり12%でドロップ |
| 上手い場合の期待 | 5波で約7.8個 ≈ **0.92個/秒** |
| メーター | 十数秒で OPTION（5個）〜 ?（6個）まで到達 |

### 目標（ファミコン版グラディウス相当）

- 空中戦（地形なし、ステージ1の先頭約14秒、波1〜8）で上手く倒しても、**SPEED と MISSILE まで**。OPTION は急がない。
- SPEED → MISSILE → OPTION を選ぶのに必要な7個は、上手いプレイでステージ1の地形後半（約45秒）に届く。
- 1画面にカプセルは同時にたくさん浮かない（**同時1個**）。
- 赤1機撃破で1個。編隊全滅ボーナスは最大1個。
- **同じ波からカプセルは複数出ない**。赤がいる波は赤のみ。通常波は全滅時のみ1個（しかも全滅ボーナス波に限る）。

## 1. 固定タイムステップ

### 定数

| 名前 | 値 | 意味 |
|---|---|---|
| `FRAME_MS` | `1000 / 60` （約16.6667ms） | 1シミュレーションステップの長さ。`16` への切り捨ては禁止 |
| `MAX_STEPS` | `5` | 1表示フレームで進めてよい最大ステップ。83.3ms分まで追いつく |

表示は毎 `requestAnimationFrame` で1回。シミュレーションだけを `steps` 回回す。補間（interpolation）はしない（ファミコン画素なので最新状態をそのまま描く）。

### ポーズ中の `acc` 処理（必須）

ポーズ中（`S.mode === "paused"`）は **経過時間を一切積まない**。

- 毎表示フレーム: `last = now`, `acc = 0`, `steps = 0`
- ポーズ解除直後に catch-up しない（止まっていた秒数だけ敵が進む事故を防ぐ）
- タブ非表示でポーズに入る現行処理はそのまま。入った時点で `acc` を捨てる

`dying` / `clear` / `ending` / `gameover` / `title` はポーズではない。タイトル点滅や死亡演出タイマーは通常どおりステップする。`gameover` / `ending` のゲーム進行が止まるのは現行どおり呼び出し側の早期returnでよい。時計自体は進めてよい（HUD点滅用）。

### スパイラル・オブ・デス

`acc` が `FRAME_MS * MAX_STEPS` を超えたら、`MAX_STEPS` だけ実行し、**残り `acc` は 0 に捨てる**。タブ復帰で一度に何十フレームも進まない。

### 呼び出し側ループ（仕様）

```
clock = stepSimulationClock(now, last, acc, FRAME_MS, MAX_STEPS, paused)
last = clock.last
acc  = clock.acc
for i in 1 .. clock.steps:
    シミュレーション1回（updateTitle または updatePlay）
draw()  // 常に1回。steps==0 でも描く（ポーズ画面）
```

シミュレーション1回の長さは入力の有無と無関係。自機の移動量・ポインタ位置・キー押下を `scroll` / 敵 `vx` / 星の速度 / `waveTimer` に加算してはならない。

## 2. カプセルドロップ規則

乱数は使わない。`Math.random() < 0.12` は廃止。

### 定数

| 名前 | 値 |
|---|---|
| `MAX_ONSCREEN_CAPSULES` | `1` |
| `WAVE_PERIOD` | `8` |
| `RED_PHASE` | `3` |
| `WIPE_PHASE` | `6` |
| `FAN_COUNT` | `5`（赤波・通常波とも） |
| `RED_SLOT` | `2`（0始まり。5機の先頭から3機目が赤） |

### 波の役割（`waveIndex` は現行どおり、スポーン直前に +1。最初の波は 1）

| `waveIndex % 8` | 役割 | ドロップ |
|---|---|---|
| 1 | 通常fan×5 | なし |
| 2 | 通常fan×5 | なし |
| 3 | fan×4 + 赤×1（`RED_SLOT=2`） | **赤撃破で1個** |
| 4 | 通常fan×5 | なし |
| 5 | 通常fan×5 | なし |
| 6 | 通常fan×5 | **全滅で1個**（1機でも逃がしたら0） |
| 7 | 通常fan×5 | なし |
| 0（8,16,…） | 通常fan×5 | なし |

`isRedWave` と `isWipeBonusWave` は同時に真にならない（位相 3 と 6）。

### ドロップ判定（擬似コード）

```
shouldDropCapsule(event) → boolean

前提: 1回の撃破（または画面外逃亡）ごとに呼ぶ。内部状態は持たない。

1. event.kind !== "kill"           → false
2. event.onScreenCapsules >= 1     → false   // 同時1個。出さず権利消滅
3. event.waveDropped === true      → false   // 同じ波から2個目は出さない
4. event.waveIndex < 1             → false
5. event.enemyType が fan / fanRed 以外 → false
     （ducker / moai / turret / boss は永続的に出さない）

6. 赤撃破:
     event.red === true かつ event.waveHasRed === true → true
     （赤波の他機を全滅しても追加しない。ここに来ない）

7. 全滅ボーナス:
     event.waveHasRed === true     → false   // 赤がいる波は赤のみ
     isWipeBonusWave(waveIndex) が false → false
     event.fansEscaped > 0         → false   // 1機でも逃がしたら無効
     event.fansAliveAfter !== 0    → false   // まだ残っている
     event.fansSpawned < 1         → false
     → true

8. それ以外 → false
```

### 編隊の数え方

- カウント対象は、その `waveIndex` で出した `fan` / `fanRed` だけ。
- 同じタイミングで出る ducker / turret / moai は編隊に含めない。倒してもドロップしない。全滅判定にも使わない。
- 敵が `x < -30` で消えたら `fansEscaped += 1`。その波の全滅ボーナスは以後false。
- ボス戦中は波を出さない（現行どおり）。ボスはドロップしない。

### モアイ／砲台との干渉

現行のモアイは `scroll > 700` かつ `waveIndex % 3 === 0` のとき **fanを置換してreturn** している。これだと赤波（3, 27, …）や全滅波が消える。

**規則:** モアイは fan を置換しない。砲台と同じく **追加スポーン** にする。fan 波のスケジュール（赤／全滅）は常に消化する。

### 画面上のカプセル

- 同時上限 1。既に1個あるときに撃破しても出さない（権利は消滅。キューしない）。
- 取りに行かず画面左へ消えたら次を出せる。
- 速度は現行: `vx = -0.45` ピクセル/ステップ（60ステップ/秒で約27px/秒、横断約9.5秒）。
- 上手いプレイなら次ドロップまで約6.8秒なので、拾っていれば上限にほぼ当たらない。放置すると次を逃す。

## 3. 赤編隊の出現規則

| 項目 | 現行 | 新 |
|---|---|---|
| 頻度 | `waveIndex % 5` が 1 または 4（40%） | `waveIndex % 8 === 3`（12.5%） |
| 機数 | 赤3機 | **5機中1機だけ赤** |
| どの機が赤か | 全員 | 先頭から3機目（`i === 2`）。`type: "fanRed"`, `red: true` |
| 他4機 | — | `type: "fan"`, `red: false`。倒しても出さない |
| 速度・HP・スコア | 現行維持 | 維持（赤200点、通常100点） |
| 波間隔 | `waveInterval(stage, scroll)` | **変更しない**（敵の密度は据え置き。減らすのはカプセルだけ） |

`waveIndex` はステージクリアで 0 に戻る（現行どおり）。ステージをまたいで位相を持ち越さない。

地形付加（`scroll > 700`）:

- ducker: 現行どおり `waveIndex % 2 === 0` で追加。ドロップなし。
- turret: 現行どおり要塞で追加。ドロップなし。
- moai: 条件は現行（`% 3 === 0`、`% 6 === 0` で天井も）。**fan と同時に出す**。

## 4. 目標頻度

`waveInterval` は据え置き。ステージ0・固定60fpsで計算。

| 区間 | 間隔 | 8波サイクル |
|---|---|---|
| scroll < 700（約16秒まで） | 102f = 1.700秒 | 13.60秒 |
| scroll ≥ 700 | 92f = 1.533秒 | 12.27秒 |

### 期待値（カプセル個数）

| プレイ | 波あたり | 秒あたり（序盤） | 秒あたり（中盤） |
|---|---|---|---|
| 上手い（赤を取る + 全滅波を全滅） | **0.250**（8波で2個） | **0.147** | **0.163** |
| 赤だけ（全滅波は逃す） | 0.125（8波で1個） | 0.074 | 0.082 |
| 現行（参考） | 約1.56 | 約0.92 | 約1.0 |

### 上手いプレイの到達目安（ステージ0、取得遅れ +1.5秒込み）

| イベント | 波 | 取得時刻 | メーター |
|---|---|---|---|
| 最初の赤 | 3 | 約 6.6秒 | SPEED（空中戦） |
| 最初の全滅 | 6 | 約 11.7秒 | MISSILE（空中戦） |
| 赤 | 11 | 約 20秒 | DOUBLE欄 |
| 全滅 | 14 | 約 25秒 | LASER欄 |
| 赤 | 19 | 約 32秒 | OPTION欄（まだ急がない） |
| 全滅 | 22 | 約 37秒 | |
| 赤 | 27 | 約 45秒 | **OPTION 発動可能** |
| 全滅 | 30 | 約 49秒 | ボス直前に1個余り |

空中戦（波1〜8、約14秒）: 最大2個。SPEED → MISSILE まで。OPTION には届かない。  
ステージ1ボスまで（約51秒）: 最大8個。SPEED + MISSILE + OPTION が間に合う。?（シールド）まで放置しても端まで駆け抜けない。

ステージ2以降は `waveInterval` が短くなるため、同じ規則でもやや増える（難易度上昇として許容。周期は変えない）。

## 5. `logic.js` 純関数の入出力契約

副作用なし。`Date` / `performance` / `Math.random` / DOM を読まない。時計は `now` を引数で受け取る。

既存の `waveInterval(stageIndex, scroll)` は残す（数値変更なし）。

### 5.1 公開定数（追加）

```
FRAME_MS = 1000 / 60
MAX_STEPS = 5
MAX_ONSCREEN_CAPSULES = 1
WAVE_PERIOD = 8
RED_PHASE = 3
WIPE_PHASE = 6
FAN_COUNT = 5
RED_SLOT = 2
```

### 5.2 `stepSimulationClock(now, last, acc, frameMs, maxSteps, paused?)`

| 引数 | 型 | 意味 |
|---|---|---|
| `now` | number | `performance.now()` のミリ秒 |
| `last` | number | 前回の `now`。初回は `0` |
| `acc` | number | 未消化ミリ秒。初回は `0` |
| `frameMs` | number | 必ず `FRAME_MS` |
| `maxSteps` | number | 必ず `MAX_STEPS`（5） |
| `paused` | boolean | 省略時 `false` |

戻り値: `{ last: number, acc: number, steps: number }`

| 条件 | 戻り値 |
|---|---|
| `paused === true` | `{ last: now, acc: 0, steps: 0 }` |
| `last === 0` または `last == null`（初回） | `{ last: now, acc: 0, steps: 1 }`。巨大な `dt` は入れない |
| `now < last`（時計逆行） | `dt = 0` として以下へ |
| 通常 | `dt = now - last`。`acc += dt`。`acc >= frameMs` かつ `steps < maxSteps` のあいだ `acc -= frameMs`, `steps++` |
| `steps === maxSteps` かつ `acc >= frameMs` | `acc = 0` にして打ち切り |

不正引数: `frameMs <= 0` なら `{ last: now, acc: 0, steps: 0 }`。`maxSteps < 1` は 1 として扱う。

例（`FRAME_MS = 1000/60`）:

- `(16.667, 0, 0, FRAME_MS, 5, false)` → `{ last: 16.667, acc: 0, steps: 1 }`
- 次に `(33.333, 16.667, 0, FRAME_MS, 5, false)` → `{ last: 33.333, acc: 0, steps: 1 }`
- `(50.000, 16.667, 0, FRAME_MS, 5, false)` → `dt=33.333` なので `steps: 2`, `acc` は 0 付近
- `(1000, 0, 0, FRAME_MS, 5, false)` → 初回規則で `steps: 1`（1000msぶんは回さない）
- 初回済みのあと `now` が 200ms 飛ぶ → `steps: 5`, `acc: 0`
- `paused: true` なら `now` がいくらでも `steps: 0`, `acc: 0`

### 5.3 `resetSimulationClock(now)`

ポーズ突入・ステージ開始・コンティニュー時に呼ぶ。

- 入力: `now` number
- 出力: `{ last: now, acc: 0, steps: 0 }`

### 5.4 `isRedWave(waveIndex)`

- 入力: `waveIndex` 整数
- 出力: boolean
- 規則: `waveIndex >= 1` かつ `(waveIndex % 8) === 3`
- 例: 3, 11, 19, 27 → true。0, 1, 2, 6, 8 → false

### 5.5 `isWipeBonusWave(waveIndex)`

- 入力: `waveIndex` 整数
- 出力: boolean
- 規則: `waveIndex >= 1` かつ `(waveIndex % 8) === 6`
- 例: 6, 14, 22, 30 → true。3 → false（赤波）

### 5.6 `planWave(waveIndex)`

スポーン時に1回呼ぶ。

- 入力: `waveIndex` 整数
- 出力:

```
{
  fanCount: 5,
  isRed: boolean,      // isRedWave(waveIndex)
  redSlot: 2,          // isRed が false でも定数を返す。使うのは isRed のときだけ
  wipeBonus: boolean   // isWipeBonusWave(waveIndex)
}
```

呼び出し側は `i === redSlot` の1機だけ `red: true`。`waveHasRed = plan.isRed`。`waveDropped = false`。`fansSpawned = 5`。`fansEscaped = 0`。

### 5.7 `shouldDropCapsule(event)`

- 入力: プレーンオブジェクト（欠ける欄は「その条件を満たさない」側に倒す）

```
{
  kind: "kill" | "escape",
  enemyType: "fan" | "fanRed" | "ducker" | "moai" | "turret" | "boss",
  red: boolean,
  waveIndex: number,          // 波に属さない敵は 0 以下
  waveHasRed: boolean,
  waveDropped: boolean,
  fansAliveAfter: number,     // このイベント処理後に残っている fan/fanRed
  fansEscaped: number,        // このイベントより前に逃がした数。escape 自体は先に +1 して渡す
  fansSpawned: number,
  onScreenCapsules: number    // ドロップ前の画面上個数
}
```

- 出力: boolean（true のときだけ `dropCapsule`）。true を受けたら呼び出し側が `waveDropped = true` にする。
- 規則は第2節の擬似コードどおり。

テスト用の期待（代表）:

| event 要約 | 結果 |
|---|---|
| 赤波・赤撃破・画面0個・未ドロップ | true |
| 赤波・通常fan撃破 | false |
| 赤波・赤を倒したあと全滅 | false（`waveDropped`） |
| 赤波・赤を逃して全滅 | false（赤波は全滅ボーナスなし） |
| 波6・5機目撃破・逃亡0・画面0 | true |
| 波6・5機目撃破・逃亡1 | false |
| 波6・4機目撃破（残り1） | false |
| 波1・全滅 | false（ボーナス波ではない） |
| どの波でも `onScreenCapsules === 1` | false |
| ducker / moai 撃破 | false |
| `kind: "escape"` | false |

### 5.8 既存関数との関係

| 関数 | 変更 |
|---|---|
| `collectCapsule` / `activatePower` / メーター | 変更しない。1カプセル = 1マス。OPTION=5、?=6 |
| `waveInterval` | 変更しない |
| 敵の `vx` / スクロール 0.72 | 変更しない。ただし **1ステップあたり** の加算であり、表示フレームあたりではない |

## 6. 呼び出し側が持つ波状態（契約、実装は game.js）

各fan波について:

```
{
  waveIndex,
  hasRed,       // planWave.isRed
  dropped,      // この波で既に1個出したか
  spawned,      // 5
  alive,        // 残り fan/fanRed
  escaped       // 画面外に消えた数
}
```

撃破時: `alive -= 1` してから `shouldDropCapsule`。  
逃亡時: `escaped += 1`, `alive -= 1`。`kind: "escape"` で呼んでもよいが、戻りは常に false。
