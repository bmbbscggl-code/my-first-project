## 1. まず3分で読む！AIって何をしているの？（エグゼクティブサマリー）

スマートフォンで写真を撮ると、「ネコ」と表示されることがあります。なぜ機械がネコだと分かるのでしょう？　AIは目を持っていません。でも絵の中にある「数字の点」を小さな虫めがねで何度もなぞって、線・形・模様を少しずつ見つけ、「これはネコだ！」と当てます。このやり方を **CNN（シーエヌエヌ）** といいます。むずかしい言葉ですが、この資料を読めば、どんな仕組みか分かるようになります。

この資料では、次の3つの「なぜ？」に答えます。

- **絵はどんな数字でできているの？**
- **虫めがねって、本当は何なの？**
- **AIはどんなときに失敗するの？**

CNNは「絵を読むAI」の代表的なやり方です。今は、ほかの新しいやり方も活躍しています。でも「小さな虫めがねでなぞる」考え方を知ると、今のAIが何をしているか、ぐっと分かりやすくなります。

---

> ### 📌 保護者・先生向け補足コラム①
> CNN（Convolutional Neural Network：畳み込みニューラルネットワーク）は画像認識の標準的な仕組みです。現在の最先端では Transformer 系の手法も多く使われており、「画像認識＝CNNのみ」ではありません。「AIは目を持たない」は比喩ではなく事実です。入力は数値の配列であり、光や色を「感じる」のはカメラセンサが行う別処理です（CS231n）。

## 2. なぜ機械が「絵を読む」ことを学んだの？（背景と課題）

**機械が絵を読む技術は、人間の「困りごと」から生まれました。**

むかし、郵便局では手紙を仕分けする人が「郵便番号」を目で読んで、手で仕分けをしていました。1968年、日本では機械が数字の絵を読んで手紙を仕分けする装置が登場しました（東京中央郵便局で公開）。毎時20,000通を処理できました。これは今の画像認識AIとは別の仕組みですが、「機械に絵を読ませたい」という夢の始まりでした。

その後、1980年に日本の福島邦彦（ふくしまくにひこ）さんが、人間の脳の「ものを見る仕組み」をヒントにした「ネオコグニトロン」というモデルを発表しました。人間の目の神経（視覚皮質：しかくひしつ）が線を見たり形を見たりする働きを、数学で真似しようとしたのです。

そして今は、スマートフォンで毎日たくさんの写真が生まれています。人間が全部見て仕分けるのはとても無理です。だから機械に「絵を読む」ことを教える研究が続けられてきました。

> **考えてみよう！** あなたのお家の写真アプリで、「犬の写真だけ探せる機能」はありますか？　あれも、似たようなAIの仕組みが使われています。

---

> ### 📌 保護者・先生向け補足コラム②
> 1968年の郵便番号OCR（東芝TR-3/TR-4）は古典的なパターン認識であり、CNNや機械学習ではありません（情報処理学会コンピュータ博物館）。歴史的な「機械が数字の絵を読む」例として有効です。福島邦彦のネオコグニトロン（1979年日本語論文、1980年英語論文）は現代CNNの先駆とされますが、学習方式が現代のCNN（誤差逆伝播）とは異なります（教師なし自己組織化）。写真アプリの現行モデルがCNNかViT（別の仕組み）かは非公開のものが多く、断定的な記述は避けています。

## 3. 虫めがねで絵を読む仕組み（技術概要）

### 3-1. 絵は「点の数字」でできている

**デジタル写真は、小さな正方形の「点（ピクセル〈画素〉）」が大量に集まってできています。**

写真をパソコンで大きく拡大してみると、小さな色のついたマス目が見えます。あの1つひとつが「ピクセル」です。各ピクセルは赤・緑・青（RGB）の3つの数字で色を表しています。それぞれ0（暗い）〜255（明るい）の数字で、組み合わせは約1677万色（256×256×256）あります。

```
[ 写真を拡大するとこんなふうに見える ]

■■■□□□□□□□
■■□□□□□□□□    ← 実際は色数字の並び
□□□□□■■□□□    (例: 赤=240, 緑=180, 青=60)
□□□□■■■■□□
□□□■■■■■□□
□□□□■■■□□□
```

つまりAIに届く「絵」は、こんな数字の表です。

```
┌────────────────────────────────────┐
│  ピクセル(0,0)  ピクセル(1,0)  ...  │
│  赤:240         赤:230               │
│  緑:180         緑:175               │
│  青: 60         青: 55               │
│  ...            ...                  │
└────────────────────────────────────┘
```

AIは「目」ではなく「数字の計算」で絵を読んでいます。

---

### 3-2. 小さな虫めがねで絵をなぞる（フィルタ＝畳み込み）

**AIの虫めがね（フィルタ〈ひとつのパターン検索機〉）は、3×3マスの小さな窓のようなものです。**

この窓を絵の左上から右下まで少しずつずらしながら、絵の上を「なぞっていく」操作を **畳み込み（たたみこみ）** といいます。

```
[ 虫めがねが絵をなぞる様子 ]

絵（数字の表）         虫めがね（3×3）
┌──┬──┬──┬──┬──┐     ┌───┬───┬───┐
│  │  │  │  │  │     │ 1 │ 0 │-1 │
├──┼──┼──┼──┼──┤     ├───┼───┼───┤
│  │▓▓│▓▓│▓▓│  │  →  │ 2 │ 0 │-2 │  ← 縦線を探すフィルタ
├──┼──┼──┼──┼──┤     ├───┼───┼───┤
│  │▓▓│▓▓│▓▓│  │     │ 1 │ 0 │-1 │
├──┼──┼──┼──┼──┤     └───┴───┴───┘
│  │  │  │  │  │
└──┴──┴──┴──┴──┘
      ↓ 窓をずらして繰り返す
   「特徴マップ（虫めがねが作る地図）」ができる
```

窓を当てた部分の数字をフィルタの数字と掛け合わせて足すと、「ここに縦線があるかどうか」が1つの数字で出てきます。これを絵全体で繰り返すと、「縦線があった場所の地図（特徴マップ）」が完成します。

---

### 3-3. 大事なところだけ残して小さくする（プーリング）

**大きな地図をギュッとまとめる操作を「プーリング」といいます。**

2×2マスの中で一番大きな数字だけを残して、あとは捨てます（最大プーリング〈マックスプーリング〉）。スタンフォード大学の講義（CS231n）によると、2×2・ストライド2のプーリングで空間サイズが半分になり、全体の約75%の情報が落ちます。

「情報が75%も消えて大丈夫？」と思うかもしれません。でも「縦線がこのへんにあった」という大まかな場所さえ分かれば、ネコかどうかの判断には十分なのです。細かい位置より「何があったか」が大事だからです。

---

### 3-4. 何回も重ねて「大きな形」を見つける（階層的特徴）

**「虫めがね→まとめる」を何回も重ねることで、AIは小さな線から大きな物体まで見つけられるようになります。**

研究者のZeiler & Fergus（2014年、ECCV）がAlexNetの各層を調べたところ、次のようなことが分かりました（ILSVRC-2012検証セット、AlexNet系モデル）。

```
[ 層を重ねるごとに見つかるものが変わる（典型的な例）]

1〜2層目 → 斜めの線、角、色の境目
3層目   → テクスチャ（網目模様、ざらざら感）
4層目   → 物体の部品（犬の顔、鳥の足）
5層目   → 全体の形（キーボード、犬など。ここではネコにも置き換えて考えます）
```

> **注意**: これは可視化研究の典型的な例です。すべての層・すべてのモデルで必ずこの順になるわけではありません（Zeiler & Fergus 2014 は背景の草に反応する特徴マップも報告しています）。

ブロックを積み重ねていくと、最後に建物の形が見えてくる——それに似ています。

---

### 3-5. 何回も見て覚える（学習）

**正解つきの写真をたくさん見せて、虫めがねの「目盛り（重み）」を少しずつ直していく操作を「学習」といいます。**

最初、フィルタの数字（重み）はでたらめです。AIは「ネコ」と正解ラベルのついた写真を見て、間違えたら重みを少し修正します。これを何十万枚と繰り返すうちに、正しく当てられるようになります。

2012年の研究（ILSVRC-2012）では、訓練に1,281,167枚の写真と1000種のラベルを使いました（Russakovsky et al., 2015）。「1枚では覚えられない」——これが学習の鉄則です。

---

> ### 📌 保護者・先生向け補足コラム③
> 「フィルタ（カーネル）」の技術的定義は畳み込み演算の重み行列です。「虫めがね」は論文用語ではなく教育用比喩です（CS231nの用語は "slide each filter"）。層の「線→形→物体」は経験的観察です。Layer 1の基本的なエッジ検出はCS231nなどの一般的知見、Layer 2〜5の可視化はZeiler & Fergus（2014）に基づきます。すべての層・モデルで厳密にこの順とは限りません。「1枚では覚えられない」は原則ですが、転移学習（Teachable Machineが使う方法）では少ない枚数でも動作します（後述）。ImageNet約128万枚（ILSVRC-2012訓練セットの正確な値は1,281,167枚）は2012年のデータであり、現行アプリの学習規模を保証しません。

## 4. 虫めがねの中身をもっとくわしく（詳細設計・仕様）

### 4-1. 虫めがねが何枚もある

**1つの仕組みの中に、役割の違う虫めがねが何十枚もあります。**

「縦線を探す担当」「斜め線を探す担当」「丸い形を探す担当」など、それぞれが別の特徴マップ（とくちょうマップ：見つけた場所の地図）を作ります。たくさんの虫めがねが並行して絵を調べるので、複雑な模様も見つけられます。

---

### 4-2. 「0より小さい数はゼロにする」ルール（ReLU）

**マイナスの数を全部ゼロにする操作を「活性化（かっせいか）」といい、特に「ReLU（アールイーエルユー）」という方法がよく使われます。**

計算の途中でマイナスになった部分は「何も見つからなかった」ことを意味します。それをスッキリゼロにしてしまいます。暗くて何も見えない場所を真っ黒にする、という消しゴム操作のイメージです。

---

### 4-3. 最後の判定（全結合層と確率）

**集めた特徴をすべてまとめて、「ネコ70%・イヌ20%・ウサギ10%」のような確率（かくりつ）に変える部分を「全結合層（ぜんけつごうそう）」といいます。**

一番大きな数字のクラスが「予測（よそく）」として出力されます。つまりAIは「これは絶対ネコだ」ではなく「70%の自信でネコだと思う」という答えを出しているのです。

---

### 4-4. 実際のモデルの大きさ（歴史的な数字で感覚をつかむ）

**2012年の「AlexNet（アレックスネット）」という研究用のAIは、約6000万個のパラメータ（目盛り）を持ち、2台のGPU（グラフィック専用の計算チップ）で5〜6日かけて学習しました（Krizhevsky et al., 2012）。**

| 記録 | 数値 |
|---|---|
| 層の数（畳み込み5＋全結合3） | 8層 |
| パラメータ数 | 約6000万個 |
| 学習にかかった時間 | 約5〜6日（2GPU） |
| ILSVRC-2012テスト top-5 誤り率 | 15.3%（2位は26.2%） |

> **★注記**: これは2012年の研究用コンテストの数字です。今のスマートフォンアプリのAIの中身は非公開で、さらに進化しています。この数字を現行製品の精度と混同しないでください。

---

### 4-5. 画像の形と数字の大きさ（スケール感）

**写真を「数字の表」として見たとき、どのくらいの量になるでしょうか。**

| 画像の種類 | サイズ | 数字の個数 |
|---|---|---|
| 手書き数字（MNIST） | 28×28（1色） | 784個 |
| 小さなカラー写真（CIFAR-10） | 32×32×3色 | 3,072個 |
| 標準的なカラー写真 | 224×224×3色 | 約15万個 |

224×224の写真を1枚送ると、AIは約15万個の数字の計算を始めます。

---

> ### 📌 保護者・先生向け補足コラム④
> AlexNetの「パラメータ約6000万」はKrizhevsky et al.（2012）の一次論文の値です。現行製品のモデルサイズとは無関係です。「15万個の計算」はCS231nの規模感説明を参考にした教育的概数です。ReLU（Rectified Linear Unit）は `max(0, x)` の関数で、AlexNet（2012）以降に普及しました。数学的詳細は中学・高校レベルです。

## 5. じぶんでAIを作ってみよう！（実装計画）

**Teachable Machine（ティーチャブル・マシン）という無料のブラウザツールを使えば、自分だけのAIを作ることができます。**

### 必要なもの

- パソコンまたはタブレット（カメラ付き）
- インターネット接続
- Webブラウザ（Google Chromeなど。授業前にカメラが動くか確認してください。iPadのSafariでは動かないことがあるので、可能ならChromeまたはパソコンで試す）
- 保護者または先生の付き添い（初回推奨）

---

### ステップ① AIに「正解の写真」を見せる（学習フェーズ）

1. Teachable Machine（`https://teachablemachine.withgoogle.com/`）をブラウザで開く
2. 「新しいプロジェクト」→「画像プロジェクト」を選ぶ
3. グループ1「ネコ」にネコのぬいぐるみや絵を**30枚以上**ウェブカメラで撮影する
4. グループ2「イヌ」に同様に**30枚以上**撮影する
5. 「トレーニング」ボタンを押す

> **⚠️ 大切な約束**: 人の顔や友だちはカメラで撮影しないようにしましょう。使う場合は、必ず先生か保護者に相談してください。

> **「何枚撮ればいい？」** Google Codelabsでは「各クラス少なくとも30枚」を目安としています（デモ最小）。多いほど安定します。少ない枚数でも動くのは転移学習のおかげです（保護者コラム⑤を参照）。

---

### ステップ② カメラに写してみる（推論フェーズ）

- 学習に使ったものと同じ向き・明るさで写すと当たりやすい
- 違う向き・暗い場所・背景が変わると失敗することを体験してみよう

---

### ステップ③ 失敗させてみる（限界の体験）

| 条件の変化 | 予想 |
|---|---|
| ライトを消して暗くする | → 当たるかな？ |
| 横から写す | → 当たるかな？ |
| 背景を白い紙に変える | → 当たるかな？ |
| カラフルな布の上に置く | → 当たるかな？ |

印西市立原山小学校（2023年〜）の実践でも、「背景や写り込みで結果が変わる」ことを児童自身が発見する体験が報告されています。

---

### ステップ④ 「なぜ失敗したか」を考える

- 「学習したときの写真と、今の写真の何が違った？」
- 「光・角度・背景——どれが一番影響した？」
- 結果をメモして比べてみよう（科学の第一歩！）

---

### 発展体験（先生・保護者と一緒に）

- Scratch（TM2Scratch）につないでじゃんけんゲームを作る（みらプロ「みらたん」事例）
- 野菜の種類を当てるAIを作る（きゅうり農家の事例と接続）

> **所要時間の目安**: ステップ①〜③で約30〜45分。発展体験でさらに30〜60分。

---

> ### 📌 保護者・先生向け補足コラム⑤
> Teachable MachineはMobileNet（CNN系の小型モデル）の**転移学習**を使用しています。「ゼロからCNNを学習」ではなく、既に1,000種の物体で学習済みの特徴抽出器の上に分類器を追加する方式です（Coral公式ページ）。少ない枚数でも動くのはこのためです。「CNN全体が30枚で学習できる」ではないことを子どもに正確に伝えたい場合は補足をお願いします。Teachable Machineの継続提供状況や推奨代替ツールは授業実施前にご確認ください（調査日2026-09-02時点では提供継続）。みらプロ（文部科学省・Google連携）指導案集（令和元年度版）はTeachable Machine＋TM2Scratchを紹介しています。

## 6. AIがうまくできているか確かめよう（評価基準・検証方法）

**「正しさ」は「当たった割合（正答率）」という数字で確かめます。ただし、何に対して当てたか、も大事です。**

### 6-1. 「当たった回数」で点数をつける

10枚見せて8枚当たったら「正答率80%」です。しかし「学習に使った写真」と「テスト用の写真」を混ぜてはいけません。テストは「まだ見たことのない写真」でやることが大切です。

---

### 6-2. 大きなテスト大会（ILSVRCの話）

研究者が世界中で「絵当てコンテスト（ILSVRC：アイエルエスブイアールシー）」を行いました。2012年、AlexNetというAIが1000種類の画像を分類し、2位より10ポイント以上良い結果を出して大活躍しました（top-5テスト誤り率：AlexNet 15.3%、2位 26.2%、Krizhevsky et al., 2012）。

> **★注記**: これは2012年の研究用コンテストの数字です。今のスマートフォンアプリの精度ではありません。

---

### 6-3. 人間と比べてみると

ある研究（2014〜2015年、Russakovsky et al., 2015 / Karpathy, 2014）では、訓練した専門家でも1000種類の写真テスト（1500枚）で約5.1%まちがえました。同じ頃、トップクラスのAIはその誤り率を下回り始めました。

> **★重要注記**: これは特定のテスト・特定の専門家・特定の評価手順での比較です。「AIが人間を完全に超えた」という意味ではありません。現在のアプリの精度を保証しません。

---

### 6-4. 子どもが自分でテストする方法

1. Teachable Machineで「テスト用」と「学習用」を分けて試してみる
2. 「明るい部屋で10枚」「暗い部屋で10枚」と条件を変えて点数を比べる
3. 結果をメモして「どんな条件で失敗したか」を書いてみよう

```
[ テスト記録シートの例 ]

条件            当たった数   正答率
────────────────────────────────
明るい部屋       8 / 10       80%
暗い部屋         4 / 10       40%
横から           3 / 10       30%
背景を変えた     5 / 10       50%
```

---

> ### 📌 保護者・先生向け補足コラム⑥
> ILSVRCの正式数値：AlexNet（2012）top-5テスト誤り率15.3%（5モデル平均）、単体18.2%、2位26.2%（Krizhevsky et al., 2012）。人間アノテータのtop-5誤り率5.1%は2014〜2015年時点の熟練者1名・1500枚サンプルでの結果（Russakovsky et al., 2015; Karpathy, 2014）。初心者5名では74〜89%という別計測もあります。ResNet（ILSVRC 2015）はアンサンブルで top-5 誤り 3.57%、単一モデル ResNet-152 は validation top-5 4.49%（He et al., 2016）。「AIが人間を超えた」はこの特定のコンテスト・特定の評価手順での話であり、現在のアプリ精度への一般化はできません。テストと学習データを分ける重要性（データ汚染防止）は機械学習の基礎中の基礎です。

## 7. まちがえること・こわい使いかた・気をつけること（リスクと対策）

**AIは100%正しいわけではありません。でも、どこでまちがえるかを知っていれば、上手に使いこなせます。**

### 7-1. AIはまちがえる

光・角度・背景が変わると、AIは失敗しやすくなります（ステップ③で体験しましたね）。「100%当たるAI」はどこにもありません。自動車の標識認識も、病院のAIも、「おかしいな」と思ったら人間が必ず確認します。

---

### 7-2. 「魔法の汚れ」でまちがえる（敵対的事例）

人間の目にはほとんど分からないくらいの小さなノイズ（雑音）を写真に加えると、AIが全く違うものと判断することがあります。

研究者のGoodfellow et al.（2015年、ICLR）の有名な実験では、GoogLeNetというAIがパンダの写真（信頼度57.7%）に非常に小さなノイズ（ε=0.007）を加えただけで、テナガザル（99.3%の信頼度）と判断してしまいました。

> これは研究者が意図的に作った「最悪のケース」です。日常の写真がいつもこうなるわけではありません。しかし「人間には同じに見えても、機械は全然違うと判断しうる」ことは事実です。

---

### 7-3. データに偏りがあると不公平になる

AIが学習する写真に「偏り（かたより）」があると、一部の人に不公平な結果を出すことがあります。

Buolamwini & Gebru（Gender Shades, 2018年）の研究では、ある商用の性別判定システムで「明るい肌の男性」の誤り率は最大0.8%だったのに対し、「暗い肌の女性」の誤り率は最大34.7%という大きな差がありました。

> **★注記**: これは2018年（約8年前）の研究であり、現行製品の精度ではありません。ただし、「学習データの偏りが結果の不公平につながる」という構造的な問題として今も重要な事例です。

> **子どもへのメッセージ**: AIが出した答えが、みんなに同じくらい正確かどうか、確かめることが大切です。

---

### 7-4. 医療や安全に使うときは必ず人間が一緒

病院の内視鏡AIは「お医者さんの補助（ほじょ）」です。AIだけで病気を決めることはありません。オリンパスの「EndoBRAIN（エンドブレイン）」（2019年発売、2018年薬事承認）は約6万枚の内視鏡画像で学習し、感度96.9%・正診率98.0%という後ろ向き試験結果を持っています。しかし添付文書には「医師の補助」と明記されています。

スマートフォンのFace ID（フェイスアイディー）は、顔の立体情報を読み取る約3万個の赤外線ドットを使った特別な仕組みです（Apple公式）。普通の写真をCNNで分類する方式とは根本的に違います。他人が開けてしまう確率は約100万分の1とAppleは発表していますが、一卵性双生児や13歳未満では誤一致のリスクが高くなることも公式に注記されています。これはあなたが悪いことをするわけではなく、顔の特徴がまだ変化している成長期のためです。大人と一緒に使う分には問題ありません。

---

### 7-5. 子どもが気をつけること

- 自分や友だちの顔の写真をAIに学習させるときは、必ず保護者・先生に相談する
- 「AIが言ったから正しい」ではない——「なぜそう言えるの？」と考える習慣を持とう
- AIが怖くなったら、大人に話してみよう

### 7-6. リスクと対策のまとめ

| リスク | 起こりやすさ | 影響 | 対策 |
|---|---|---|---|
| 光・角度・背景でまちがえる | 高 | 中 | いろいろな条件でテストする。人間が確認する |
| 「魔法の汚れ」で別物と判断する | 低（研究用の最悪ケース） | 大 | 大事な判断は人間が確認する |
| 学習データの偏りで不公平になる | 中 | 大 | いろいろな人・場所・状況の写真で確かめる |
| 顔写真の無断学習 | 中 | 大 | 人の顔は撮らない。使うなら大人に相談 |
| 医療・安全をAIだけで決める | 低（ルールで禁止） | 大 | 病院のAIは「お医者さんの補助」。AIだけで決めない |

---

> ### 📌 保護者・先生向け補足コラム⑦
> 敵対的事例（adversarial examples）：Szegedy et al.（ICLR 2014）、Goodfellow et al.（ICLR 2015）の研究に基づきます。パンダ→テナガザルの例はGoogLeNet・ε=0.007の摂動で、研究者が意図的に作った最悪ケースです。日常写真がいつも壊れるわけではありませんが「見た目が同じでも機械は別物と判断しうる」は事実です。Gender Shades（Buolamwini & Gebru, 2018）：商用性別分類3システムでの格差。2018年時点の調査であり現行製品の精度ではありませんが、データ偏りの構造的問題として今も重要な参照点です。Face ID（Apple）：TrueDepthカメラで約3万個の赤外線ドット投影→深度マップ＋赤外画像→専用Neural Engineで照合する方式であり、「2D写真のCNN分類」とは設計が根本的に異なります。医療AI（EndoBRAIN）の感度96.9%・正診率98.0%は後ろ向き試験の結果であり、前向き試験や全病院での性能を保証しません（オリンパス2019年リリース）。文科省の生成AI暫定ガイドライン（2023年〜）および各教育委員会の方針を確認した上で体験活動を設計することを推奨します。

## 8. もっと知りたい人へ（付録）

### 8-1. この資料で出てきた言葉の一覧（用語集）

| 言葉 | 説明 |
|---|---|
| **ピクセル（画素）** | デジタル写真を作る最小の点。それぞれ赤・緑・青の数字（0〜255）で色を表す |
| **CNN（シーエヌエヌ）** | Convolutional Neural Network（畳み込みニューラルネットワーク）。虫めがね方式で絵を読むAIの仕組み |
| **フィルタ（虫めがね）** | 絵の上をずらしながら「何が見つかるか」を計算する小さな窓（3×3マスなど） |
| **畳み込み（たたみこみ）** | フィルタを絵全体になぞる操作。絵の中の線・模様・形を数字で見つける |
| **特徴マップ** | 虫めがねが作る「見つけた場所の地図」 |
| **プーリング** | 特徴マップをまとめて小さくする操作。大事な部分だけ残す |
| **重み（おもみ）** | フィルタの中の数字（目盛り）。学習によって自動的に決まる |
| **学習（がくしゅう）** | 正解つき写真をたくさん見せて、重みを少しずつ修正していく操作 |
| **ReLU（アールイーエルユー）** | マイナスの数をゼロにする操作。活性化関数の一種 |
| **確率（かくりつ）** | 「どのくらい自信があるか」を0〜100%で表した数字 |
| **転移学習** | 別のデータで学習済みのAIに、新しいことを少ない枚数で追加学習させる方法 |
| **敵対的事例（てきたいてきじれい）** | 人間には見分けられないほど小さな変化でAIを騙す特殊な例 |

### 8-5. 想定Q&A（子どもが聞きそうな問い＋保護者が聞きそうな問い）

**Q1（子ども向け）: AIは本当に「見ている」の？目があるの？**

A1: AIには目がありません。カメラが光を数字に変えて、AIはその数字の計算をしているだけです。「見る」「分かる」は人間の言葉を借りた比喩です。本当のところは「数字を足したり掛けたりしているだけ」です。

---

**Q2（子ども向け）: AIが怖いんだけど、大丈夫？**

A2: AIを怖いと思う気持ちは大切です。AIはとても便利ですが、まちがえることもあります。「AIが言ったから必ず正しい」ではなく、「おかしいな」と思ったら大人に聞いたり、自分で考えたりすることが大事です。AIを「道具」として使うのは、ハサミの使い方を学ぶのと同じです。

---

**Q3（子ども向け）: Teachable Machineで作ったAIはスマホのAIと同じ？**

A3: 仕組みは似ていますが、規模がまったく違います。Teachable Machineは「学習済みの大きなAIの上に、自分用の分類を追加する」方法（転移学習）なので、少ない枚数でも動きます。スマホのアプリは、もっとたくさんのデータで長い時間をかけて作られています。

---

**Q4（保護者向け）: 子どもの顔の写真をTeachable Machineに学習させても大丈夫ですか？**

A4: Google公式ブログ（2019年、Teachable Machine 2.0）によると、撮影した例は端末の中に留まり、Googleドライブへ保存することを選ばない限りコンピュータの外に出ません。学習もブラウザ内で行われます。公式サイトも「webcamやマイクのデータをコンピュータの外に出さずに使える」と説明しています（調査日2026-09-02時点）。ただし、プロジェクトをGoogleドライブに保存したり、一部の書き出し機能を使うとデータが端末外に出ることがあります。個人情報への配慮として、子どもの顔や友人の顔を無断でAIに学習させることは控えてください。授業で使う場合は、学校の規定や文部科学省のAIガイドライン（2023年〜）をご確認ください。

---

**Q5（保護者向け）: この資料のデータはどこまで信頼できますか？**

A5: 各数値には出典を明記しています。ただし、AlexNet（2012年）・Gender Shades（2018年）・EndoBRAIN（2019年）など多くの数値は3年以上前のものです。歴史や仕組みの説明には使えますが、現在のスマホや病院のAIの性能として使うことはできません。「これは○○年の研究の話」として理解してください。

---

**Q6（保護者向け）: 医療AIはどのくらい信頼できますか？**

A6: オリンパスEndoBRAINは後ろ向き試験で感度96.9%・正診率98.0%という結果が報告されています（2019年）。ただし、これは特定の試験条件での数値であり、すべての患者・病院での性能を保証するものではありません。日本の薬事承認文書には「医師の補助」と明記されており、AIが単独で診断を下すことはありません。

---

**Q7（子ども向け）: きゅうり農家のAIって本当にあるの？**

A7: あります！静岡県の農家・小池誠さんが、お母さんの9段階のきゅうり選別をAIに覚えさせました。約2,475枚の写真でAIを作り、正答率約8割の試作品ができたと取材記事に報告されています（マイナビ農業 2019年）。AIを使って農家の仕事を楽にしようという取り組みです。
